# QuSpin 1.0.1 compatibility capability matrix

This matrix is derived from the unchanged 73-file upstream test snapshot. A
row is complete only when the original test executes through the public Python
compatibility package and the exercised behavior is covered by Rust tests.

## Remaining foundation gaps

| Priority | Required behavior | Rust/core gap | Boundary or Python gap |
|---|---|---|---|
| P1 | Wide-state subsystem analysis | scalar and matrix-valued finite-group sectors, square operators, isometric projectors, and same-storage cross-sector actions now use generic wide-state paths; the remaining dense subsystem kernel still scatters through an explicitly enumerable full tensor product | ordinary wide Hamiltonians, `get_proj(pcon=True)`, shift-sector actions, and `kblock+pblock` matrix sectors work; wide partial traces/entropy still need a sector-native sparse contraction, because constructing an unrestricted `2^N` parent above 24 binary sites is intentionally rejected |
| P2 | Exact QuSpin fixed-width NumPy dtype identity | Rust owns validated `U256`, `U1024`, `U4096`, and `U16384` values and the C boundary preserves their logical widths through decimal serialization | Python currently exposes wide basis states as exact object-integer arrays; it does not register QuSpin's native custom NumPy dtype objects, so dtype identity/itemsize checks outside the frozen suite are not equivalent |
| P1 | Arbitrary matrix-valued symmetry representations in the public general-basis constructor | finite generated-group closure and arbitrary finite-dimensional representation rows are implemented and directly tested | the serializable boundary accepts representation matrices and built-in momentum/reflection adapters use them, but the public Python constructor only exposes QuSpin's scalar-sector block-map form |
| P1 | Portable basis archives | basis requests are already serializable and persistent operator archives preserve components, formats, defaults, and scalar dtype | there is no versioned basis archive/load API yet; Python object pickling is not a portable substitute |
| P2 | Advanced legacy execution-control knobs | Rust eigensolvers consume `k`, target/shift, Krylov dimension, tolerance, iteration budget, eigenvector selection, and `v0`; subsystem analysis, user bases, and Lanczos each use one stable native path | extra SciPy-specific `eigsh` kwargs and implementation hints such as `sparse_diag`, `parallel`, `Ns_block_est`, `full_ortho`, and some copy/verbosity flags are accepted for call compatibility but do not select distinct backend algorithms |
| P2 | Incidental compatibility fidelity | the scientific kernels and documented public classes/functions are implemented | exact warning text/category, some exception wording, and non-documented imported helper names such as partial-trace phase helpers remain intentionally non-identical |

## Acceptance rule

Moving a file from `unsupported` to `passing` requires all of:

1. the copied upstream file remains byte-for-byte unchanged;
2. its original test entry points execute in CI;
3. new general Rust behavior has direct Rust tests;
4. the implementation does not branch on a model or test name;
5. the compatibility status remains exhaustive across all 73 files.
